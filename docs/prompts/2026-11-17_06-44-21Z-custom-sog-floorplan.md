# 2026-11-17 06:44:21 UTC — Implement local SOG environments with user-drawn walkable floorplans

In `kurvantu/gaussian-office` (PlanWalk Studio), implement and test this feature, not just a design. A user must be able to load their own `.sog` environment and **draw the floorplan that determines where the guide can walk**. The SOG is scenery, not collision geometry. Do not infer a floor from the splats or reuse the office footprint.

**User flow:** Scene picker → Import environment (.sog) → Align scan → Draw walkable area → Place guide start → Start exploring.

1. **Import.** Accept a local, self-contained SOG v2 file of the kind already supported by Spark. Keep the bytes in the browser. Show the filename, loading state, Cancel, and actionable errors. Validate more than the extension; document and enforce file and decoded-resource limits that admit the bundled office sample. A failed or cancelled import must leave the current scene intact.
2. **Align.** Start with an empty custom plan: no office walls, furniture, stops or spawn. In Split view, show a metre grid and the draft footprint overlaid on the scan so the user can see what they are tracing. Provide up-axis/flip, yaw, uniform scale and XYZ offset controls to put the floor at world Y=0. Apply registration to the capture, not to the guide. Never apply the bundled office’s transform based on a filename.
3. **Draw.** Add a labelled **Draw walkable area** tool to the 2D editor. Click/tap vertices, show the live outline, then Finish or Cancel. Support one or more simple polygons, including concave ones; allow undo and deletion/redrawing. Reject self-intersections and degenerate shapes. Require a valid start marker inside the walkable area before enabling walking. V1 is one flat level; no holes, stairs, automatic reconstruction or cloud storage.
4. **Walk.** In custom scenes, the authored polygons minus blocking walls/furniture are the navigation boundary for every guide command, including 2D, minimap and 3D floor clicks. Pick the authored floor proxy, not the scan, terrace or an infinite ground plane. Use the same guide root for Elena or an inserted GLB, the map marker and the tour camera. Invalid or disconnected destinations must not snap, teleport or start a partial walk. Editing/undoing a boundary must cancel unsafe routes; if the current position becomes invalid, pause and ask for a new valid start.

**Implementation constraints:** Inspect `src/scene/officeEnvironment.ts`, `src/components/{Scene3DViewport,Floorplan2DEditor}.tsx`, `src/App.tsx`, `src/types/floorplan.ts` and `src/utils/pathfinding.ts`. Reuse Spark’s SOG decoder and LOD budgets. Keep capture identity/resources separate from editable plan data and undo history. Decode once per import; edits, camera, quality and renderer changes must not reload it. Dispose replaced resources and ignore late loads. Gaussian mode shows the capture and guide; triangle mode shows the navigation proxy and guide. Preserve existing presets and Inspect Guide.

`NavGrid` currently derives bounds from walls and allows nearest-cell/best-effort paths. For custom plans, bound the grid from the polygons, cap its allocation, and enforce the footprint and guide clearance on **whole route segments**, including diagonals and smoothing—not just endpoints. Keep existing preset behavior unchanged.

**Prove it works:** Add navigation tests and a Playwright workflow using the existing `data/sog/office.sog` bytes under a different local filename; do not add another large asset. Through the UI, draw an L-shaped floor, place the guide, and click a point on the other arm. Verify the actual guide reaches it without crossing the missing corner. Click in the notch and confirm it stays put. Cover walking before setup, invalid polygons, edits/undo, failed or cancelled replacement, renderer switching without re-decoding, and returning to a built-in preset. Update README with the workflow and limits. Run `npx tsc --noEmit`, `npm run test:humanoid`, `npm run build` and `npx playwright test`; report results and how to try it.
